# Безопасность, персональные данные, ответственный ИИ

## Модель угроз (кратко)

| Угроза | Где | Контроль |
|---|---|---|
| Доступ к данным чужого клиента (IDOR) | Все API | `client_id` берётся **только** из JWT. Ни один публичный RPC и ни один инструмент агента не принимает `client_id` параметром. Репозитории фильтруют по `client_id` из контекста |
| Подбор OTP | `auth` | Хэш кода, TTL 5 мин, ≤ 3 попытки, ≤ 1 запрос в 60 с на номер, блок после 5 неудач |
| Кража сессии | Браузер | JWT в cookie `httpOnly; Secure; SameSite=Strict`, TTL 12 ч. Один origin через nginx |
| CSRF | Мутирующие запросы | `SameSite=Strict` + обязательный заголовок `X-Requested-With`, проверяемый middleware |
| XSS через ответы ассистента | Фронт | Markdown → HTML через markdown-it, затем DOMPurify. Виджеты рендерятся компонентами, а не как HTML |
| Prompt injection (через сообщение или документ) | Агент | Данные в разделителях `<data>`, белый список инструментов, нет инструментов с необратимыми действиями, валидация аргументов, client_id не управляется моделью |
| Утечка данных во внешнюю LLM | `adapters/llm` | По умолчанию on-prem модель. Для внешнего провайдера включается маскирование PII. В LLM уходят только агрегаты, без транзакций |
| Вредоносный файл | `document` | Белый список MIME (pdf, png, jpg), ≤ 10 МБ, проверка сигнатуры, имя файла не используется как путь, хранение вне web-root |
| Утечка PII в логи | Везде | Логгер маскирует телефоны, ИНН и ФИО. Тексты сообщений чата в логи не пишутся (только в БД) |
| Перебор и злоупотребление чатом | `assistant` | Rate limit на сессию и клиента, лимит длины сообщения |

## Согласия

Реализуют требования 152-ФЗ (обработка ПДн), 218-ФЗ (кредитные истории) и норм о налоговой тайне в демо-объёме.

- Каждое согласие — запись `core.consents`: источник, объём (`scope`), срок, время выдачи и отзыва. Событие пишется в `audit_log`.
- `bankdata.BuildBundle` включает данные Tier 3 **только** при активном согласии. Маска согласий — часть ключа кэша офферов.
- **Оценка выгоды от подключения считается без данных источника**: ML подставляет априорные ожидаемые значения признаков. Реальные данные источника читаются только после согласия.
- Отзыв согласия: данные источника перестают использоваться, офферы пересчитываются.
- На экране согласия простым языком: что передаётся, зачем, на какой срок, как отозвать.

## Ответственный ИИ и кредитование

| Принцип | Реализация |
|---|---|
| Решение принимает не LLM | Модель (CatBoost) + правила в Go. LLM только объясняет ([ADR-0007](adr/0007-scoring-catboost-shap.md)) |
| Объяснимость | SHAP-факторы к каждому скору. «Почему одобрено / почему нет» на экране заявки |
| Нет придуманных цифр | Guardrail проверки чисел ([ai-assistant.md](ai-assistant.md#guardrails)) |
| Раскрытие ИИ | Плашка «Ответ подготовлен ИИ-ассистентом. Предварительная оценка, не является офертой» |
| Не навязывать долг | Предупреждение, если платёж > 30% свободного денежного потока. Не предлагаем сумму выше рассчитанной платёжеспособности |
| Человек в контуре | Сумма выше `AUTO_DECISION_LIMIT` (по умолчанию 10 млн ₽) → `MANUAL_REVIEW` |
| Аудит | Каждый вызов инструмента агентом, смена статуса и согласие → `audit_log` |
| Справедливость | Не используем пол, возраст и национальность владельца как признаки модели |

## Секреты и конфигурация

- Секреты только через env (`.env` в `.gitignore`, `.env.example` в репозитории).
- `JWT_SECRET` генерируется при первом запуске, если не задан (только в DEMO_MODE).
- Ключи внешних LLM API никогда не логируются.

## Что ослаблено ради демо (и честно говорим об этом)

| Демо | В проде |
|---|---|
| Код OTP показывается в UI-тосте (`DEMO_MODE=true`) | Реальный SMS-шлюз |
| Подписание кодом из SMS | УКЭП / ПЭП по регламенту банка |
| HTTP на localhost | TLS везде, mTLS между сервисами |
| Один секрет JWT | Ротация ключей, IAM банка |
| Mock-источники | Реальные интеграции с договорами и согласиями |
