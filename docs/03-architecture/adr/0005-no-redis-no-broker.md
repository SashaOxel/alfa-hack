# ADR-0005: Без Redis и брокеров: всё на Postgres

- **Статус:** принято
- **Дата:** 2026-10-06

## Контекст
Требование: Redis и брокеры только при крайней необходимости. Типичные причины их взять: очередь задач, кэш, OTP с TTL, pub/sub для real-time.

## Решение
| Потребность | Решение без Redis / брокера |
|---|---|
| Фоновые задачи (пайплайн заявки, извлечение документов) | **River**: очередь на Postgres с ретраями, расписанием и транзакционной постановкой задачи вместе с изменением данных |
| OTP с TTL | Таблица `otp_codes` с `expires_at`, чистка периодической задачей River |
| Кэш офферов и бандлов | In-memory LRU в core (экземпляр один) |
| Real-time события в браузер | In-process pub/sub в модуле `notify` → SSE. Если понадобится несколько экземпляров core: Postgres `LISTEN/NOTIFY` |
| Rate limiting | In-memory token bucket |

## Когда пересмотреть
Несколько экземпляров core под нагрузкой или прод-интеграция с корпоративной шиной банка. Это за рамками хакатона и попадает в слайд «путь в прод».

## Последствия
- Меньше контейнеров, меньше точек отказа на демо.
- Состояние кэша теряется при рестарте. Это допустимо: всё пересчитывается из БД за миллисекунды.
