# ADR-0004: Абстракция LLM-провайдера, open-source по умолчанию

- **Статус:** принято
- **Дата:** 2026-10-06

## Контекст
Команда ориентируется на open-source LLM: это сильная история про безопасность («данные не покидают контур банка»). При этом организаторы могут выдать свой API. Формат API пока неизвестен (OpenAI-совместимый, GigaChat, YandexGPT).

## Решение
- Интерфейс `llm.Provider` в Go (`ChatStream`, `Chat`, `Embed`, `Info`).
- Основная реализация `openai_compat` на `openai-go` с настраиваемым `base_url`. Покрывает Ollama, vLLM, LM Studio и большинство облачных API.
- `gigachat` — реализуем, только если организаторы дадут GigaChat.
- Декоратор `masking` автоматически включается для внешних провайдеров.
- Отдельные настройки для чата и эмбеддингов (можно разные провайдеры).
- Режим агента `tools | router` на случай API без tool calling.
- По умолчанию: Qwen3 (8B на ноутбуке, 14B / 30B-A3B на GPU), эмбеддинги bge-m3. Финальный выбор по eval.

## Альтернативы
| Вариант | Плюсы | Минусы |
|---|---|---|
| Жёстко OpenAI / Claude API | Лучшее качество | Противоречит истории про on-prem, данные уходят наружу |
| Только локальная модель | Просто | Не готовы к API организаторов |
| LangChain-подобный фреймворк | Много готового | В Go слабая экосистема, лишняя магия. Наш цикл ~300 строк |

## Последствия
- Конфиг: `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMBED_*`, `AGENT_MODE`, `PII_MASKING`.
- На Mac Ollama запускается нативно (Docker не видит GPU Apple), core ходит в `host.docker.internal:11434`.
