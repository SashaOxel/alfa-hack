# Соглашения разработки

## Git

- **Trunk-based**: `main` всегда рабочий (поднимается через `make up` и проходит демо-сценарий). Прямой push в `main` запрещён.
- Ветки: `<type>/<area>-<кратко>`, где type — `feat`, `fix`, `chore`, `docs`; area — `web`, `core`, `ml`, `proto`, `infra`, `docs`. Пример: `feat/core-offers-engine`.
- Коммиты — Conventional Commits: `feat(core): calculate seasonal schedule`.
- PR маленькие: до ~400 строк без учёта сгенерированного кода. Мёрж — squash.
- Ревью: junior → fullstack. ML ревьюят друг друга. **Изменение proto — ревью обеих сторон** (производитель и потребитель).
- Интеграция в `main` — каждый день до 18:00, после чего смоук-прогон демо.

## Proto (без buf, поэтому дисциплина вручную)

- Пакеты `alfa.<domain>.v1`, файлы `snake_case.proto`, сообщения `PascalCase`, поля `snake_case`.
- Enum: значения с префиксом типа, нулевое — `<ENUM>_UNSPECIFIED = 0`.
- Номера полей **никогда** не переиспользуем. Удалили поле — добавили `reserved <номер>, "<имя>";`.
- Деньги — `int64 *_kop`, ставки — `int32 *_bp`, доли — `double`.
- В каждом файле `option go_package = "github.com/sashaoxel/alfa-hack/backend/gen/alfa/<domain>/v1;<domain>v1";`.
- После изменения: `make proto` и коммит сгенерированного кода в том же PR.

## Go

- `gofmt` + `goimports`, линтер `golangci-lint` (errcheck, govet, staticcheck, revive).
- `context.Context` — первый аргумент. Без глобального состояния, зависимости передаются через конструкторы.
- Ошибки оборачиваем: `fmt.Errorf("offers: build bundle: %w", err)`. В gRPC-слое превращаем в `status.Error` с кодом.
- Валидация входа — в начале метода сервиса (proto-аннотаций нет).
- Логи — `log/slog`, структурные поля, `request_id` в каждом. PII в логи не пишем.
- `client_id` — только из контекста (`auth.ClientID(ctx)`), никогда из запроса.
- Деньги — `int64` копейки. Ставки — `int` bp. `float64` допустим только внутри формул калькулятора с округлением на выходе.
- Интерфейсы объявляет потребитель (модуль), а не реализация (адаптер).
- Тесты: table-driven, `testify/require`. Бизнес-логика (`offers`, `calc`, `application`) покрыта обязательно.

## Python

- `uv`, `ruff` (lint + format), type hints везде, `pydantic` для конфигов.
- Фиксированные seed во всём, что случайно.
- Ноутбуки — только в `ml/notebooks/`. Код, который нужен в пайплайне, переносится в пакеты.
- `ml_service` не импортирует ничего из `datagen` и `training`, только `mlcore` и артефакты.
- Тесты: `pytest`. Обязательно для признаков (на фикстурах-бандлах) и инвариантов синтетики.

## Vue / TypeScript

- `<script setup lang="ts">`, Composition API, без `any`.
- API — только через сгенерированный клиент (`openapi-fetch` + `schema.d.ts`), серверное состояние — через vue-query.
- Деньги форматирует `useMoney()` (`1 284 500 ₽`), проценты — `usePercent()`.
- Виджеты ассистента живут в `src/widgets/` и регистрируются в `registry.ts`. Тот же компонент используется на обычных экранах.
- Компоненты — `PascalCase.vue`. Стили — Tailwind + токены цветов из дизайна (`--color-brand: #EF3124` и т.д.).

## Конфиги и секреты

- Секреты только в `.env` (в `.gitignore`), шаблон — `deploy/.env.example`.
- Бизнес-параметры (ставки, лимиты, правила) — в `config/*.yaml`, а не в коде.

## Definition of Done

- [ ] Работает в `docker compose` (не только локально у автора)
- [ ] Покрыто тестами, если это логика (калькуляторы, правила, признаки, state machine)
- [ ] Golden-тесты персон зелёные (офферы кофейни не «поехали»)
- [ ] Контракт изменён → proto, сгенерированный код и [api.md](../04-api/api.md) обновлены
- [ ] Нет секретов и PII в коде и логах
- [ ] Есть пустые, ошибочные и загрузочные состояния (для UI)
